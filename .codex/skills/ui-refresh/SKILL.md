# Цель
Сделать страницу инструментального класса визуально современной, строгой и консистентной:
- единый дизайн-язык через design tokens
- чистая иерархия и типографика
- меньше визуального шума
- сохранение существующей функциональности и JS-логики

# Порядок работы
1. Проанализируй текущую страницу:
   - визуальный шум
   - несогласованные отступы
   - разные стили кнопок/инпутов/карточек
   - слабую иерархию заголовков и текста
   - проблемы контраста и mobile layout

2. Сформируй дизайн-систему (token-first):
   - CSS variables для typography, spacing, radius, color roles, state, shadow
   - обязательно: `--focus-ring`, `--hover`, `--surface`, `--surface-soft`, `--muted`
   - базовые классы: `button`, `input`, `card`, `toolbar`, `section`, `badge`, `table`, `empty-state`

3. Выполни UI-рефакторинг:
   - убери случайные стили
   - выровняй сетку, отступы и ритм
   - унифицируй hover/focus/active/disabled
   - усили визуальную иерархию (header, toolbar, content blocks)
   - допускается изменение компоновки (перестановка блоков), если логика не ломается
   - если уместно, используй выразительную типографику и аккуратный атмосферный фон

4. Проверь результат:
   - desktop + mobile (от 320px)
   - sticky table headers / длинные строки / overflow
   - hover/focus/active/disabled + keyboard focus visibility
   - длинные заголовки
   - переполнение таблиц и форм
   - пустые состояния
   - контраст читаемого текста и интерактивных элементов

# Правила
- Не ломай существующую JS-логику.
- Не меняй data-атрибуты, id и хуки, используемые скриптами, без необходимости.
- Предпочитай небольшое количество хорошо определённых паттернов вместо большого числа уникальных элементов.
- Если страница выглядит “инструментальной”, делай UI строгим и функциональным, а не маркетинговым.
- Допустимы web-fonts и иконки, если это улучшает читаемость и консистентность.
- Не оставляй inline-стили там, где можно вынести в классы/токены.
- Всегда оставляй код в более чистом и поддерживаемом состоянии.

# Формат результата
1. Краткий аудит проблем UI.
2. Какие tokens и компоненты введены.
3. Что изменилось в HTML/CSS (и почему).
4. Итоговый diff.
